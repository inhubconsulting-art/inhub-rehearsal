# 대화 진행·종료 규칙과 연결·이관

> 쉬운 설명: AI 고객이 무엇을 알고, 언제 대화가 끝나고, 다른 담당자로 넘기는 상황을 어떻게 다루는지 정리한 문서입니다.

## 1. AI 고객이 아는 것 (`packages/shared/src/prompt.ts` · 고객 지시문)

| 고객에게 주는 것 | 고객에게 주지 않는 것 |
|---|---|
| 페르소나(이름·성격·말투·감정·인내심), 첫 용건, 속마음 | 수강생 브리핑의 **확인된 정보·참고 정책** |
| 고객이 아는 사실 | 필수 절차, **꼭 안내해야 할 내용**, 모범 응대, 평가 루브릭 |
| 감정 변화·만족·끊는 조건 | 연결·이관 기준 |

- 고객은 정답(규정·필요 서류 등)을 모르므로 **상담원 안내를 그대로 믿고**, 빠진 안내를 되묻지 않습니다.
- 빠뜨리거나 틀린 안내는 대화를 늘리지 않고 **리포트의 '빠뜨리거나 틀린 안내'에서 감점**됩니다.
- 고객은 첫 용건과 '고객이 아는 사실'·속마음 범위 밖의 새 요청을 만들지 않고, 답을 들은 질문은 다시 묻지 않습니다. 말버릇은 2~3번만 씁니다.

## 2. 종료 규칙 (`packages/shared/src/flow.ts`, 텍스트·음성 공통)

고객이 한 번 말할 때마다 판단 AI가 아래를 판단하고, 그 결과로 정합니다.

| 판단 | 결과 |
|---|---|
| 고객이 연결·이관(회신 약속 포함)을 받아들임 | 끝내지 않고 **'연결 대기'** → 수강생 화면에 안내 띠, 연결·이관 버튼으로 마침 |
| 고객이 마무리 인사 / 화나서 끊음 | 종료 (`resolved` / `customer_left`) |
| 용건에 답이 다 나옴 + 상담원이 마무리 인사 | 종료 (`resolved`) |
| 용건에 답이 다 나옴 (처음) | **마무리 신호**: AI 고객에게 "이제 인사하고 끝내세요" 전달 (`sessions.resolved_at` 기록) |
| 마무리 신호 후 수강생이 2번 더 말함 | 자동 종료 (`resolved`) |
| 최대 턴 수 / 제한 시간 | 종료 (`turn_limit` / `time_limit`) |

'용건에 답이 다 나옴'은 **고객 입장**의 판단입니다. 안내가 맞았는지는 따지지 않습니다(그건 평가의 몫).

## 3. 연결·이관

실제로 전화를 넘길 수는 없으므로, 실습에서는 **상담원이 할 일 두 가지**를 연습하고 평가합니다.

1. 고객에게 **말로** 연결 이유와 대기·연락 안내를 하기
2. 대화 화면 **'연결·이관' 버튼** → 연결할 곳 선택 → **다음 담당자가 읽을 인계 메모** 작성 → '연결하고 실습 마치기'

- 버튼을 누르면 `sessions.handoff = {status:"done", target, memo}` 가 저장되고 실습이 `transferred`(다른 담당자로 연결·이관)로 끝납니다. 음성이면 통화도 끊깁니다.
- 리포트의 **'연결·이관'** 카드에 필요했는지/했는지, 사유·대기 안내·인계 메모 평가와 메모 원문이 나옵니다.
- 시나리오 편집 화면에서 정하는 것:
  - **연결·이관할 수 있는 곳** (수강생 브리핑에 보임, 버튼의 선택지)
  - **연결·이관 기준** (평가에만 사용, 예: "의학적 판단 질문은 간호사 상담실로")

## 4. 시나리오를 만들 때 꼭 채울 칸

- **만족하고 마무리하는 조건**: 고객 입장의 용건 (비어 있으면 편집 화면에 경고)
- **고객이 묻지 않아도 꼭 안내해야 할 내용**: 평가의 '빠뜨리거나 틀린 안내' 기준
- **확인된 정보·참고 정책**: 수강생이 안내할 정답 (고객은 모름)
- 필요하면 **연결·이관할 수 있는 곳**과 **연결·이관 기준**
