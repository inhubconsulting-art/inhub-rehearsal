# 대화 시뮬레이터 (`npm run sim`)

시나리오마다 **여러 갈래의 응대(케이스)** 를 **서로 다른 가상 수강생**이 실제로 해 보게 하고, 서비스가 돌려주는 값을 전부 기록합니다.
직접 하나하나 실습해 보지 않아도 "어떤 상황에서 흐름이 어색하거나 오류가 나는지"를 표와 리포트로 찾을 수 있게 하는 도구입니다.

## 무엇이 서비스와 똑같고, 무엇이 다른가

| 단계 | 서비스 코드 | 시뮬레이터 |
| --- | --- | --- |
| AI 고객 지시문·마무리 신호 | `packages/shared/src/prompt.ts` | 같은 함수를 그대로 불러 씀 |
| 고객 상태 판단(감정·해결·종료·이관) | `buildClassifierPrompt` + 최근 12줄 | 같음 |
| 종료 규칙 | `packages/shared/src/flow.ts` | 같은 함수 |
| 텍스트 한 턴의 순서 | `apps/web/src/app/api/sessions/[id]/messages/route.ts` | 같은 순서로 옮김 (`engine.ts`) |
| 연결·이관 버튼 | `api/sessions/[id]/handoff` (메모 10자 이상) | 같은 규칙 |
| 평가·검증·재평가·등급 재계산 | `apps/worker/src/jobs.ts` | 같은 순서로 옮김 |
| 대화 분석(응답 시간·쿠션어 등) | `analyzeConversation` | 같은 함수 |
| 모델·사고량 옵션 | `.env` 의 `OPENAI_*` | 같은 값을 읽음 |
| 저장 위치 | 운영 DB | **파일만** (`simulations/`). 운영 DB 는 시나리오·표현 목록을 *읽기만* 함 |
| 시간 | 실제 시간 | 가상 시계: 참여자별 생각·타자 속도 + 실제 AI 응답 시간 |
| 음성 모드 | Realtime 음성 | 지원 안 함 (텍스트만). 판단·종료 규칙·평가는 음성도 같은 코드 |

`messages/route.ts` 나 `jobs.ts` 의 **순서**를 바꾸면 `engine.ts` 도 같이 맞춰 주세요. 지시문·판단·종료 규칙·검증 함수는 공통 패키지를 그대로 쓰므로 자동으로 반영됩니다.

## 실행

저장소 맨 위 폴더에서 (`.env` 에 `OPENAI_API_KEY` 필요):

```bash
npm run sim -- --quick                 # 핵심 케이스 8개 × 모든 시나리오 (처음엔 이걸로)
npm run sim                            # 케이스 18개 전부
npm run sim -- --scenarios 여권 --cases C05,C10 --repeat 3   # 골라서 여러 번
npm run sim -- --mock                  # 가짜 AI 로 흐름만 점검 (비용 0, 인터넷 불필요)
npm run sim -- --list                  # 케이스 목록
npm run sim -- --label 지시문수정후      # 실행 이름에 메모 (지시문 고치기 전/후 비교용)
```

- 시나리오는 운영 DB 의 **공개** 시나리오 현재 버전을 읽습니다. DB 접속이 안 되면 `supabase/seed.sql` 의 기본 4개로 대신합니다 (`--source seed` 로 직접 고를 수도 있음).
- 가상 수강생 모델은 `SIM_LEARNER_MODEL` (없으면 `OPENAI_CHAT_MODEL`), 사고량은 `SIM_REASONING_EFFORT` (기본 `low`).
- 비용: 실습 1회에 AI 호출이 대략 (턴 수 × 3) + 평가 1~2번입니다. 리포트와 CSV 에 실습별 추정 비용이 남습니다(서비스 몫 / 시뮬레이터 몫 따로).
- 중간에 `Ctrl+C` 로 멈춰도 그때까지 끝난 실습으로 리포트를 만듭니다.
- OpenAI 한도(429)에 걸리면 자동으로 기다렸다 다시 시도합니다. 자주 걸리면 `--concurrency 2`.

## 결과 파일

```
simulations/
  <실행ID>/
    report.html     ← 브라우저로 열어서 보기
    sessions.jsonl  ← 실습 1회 = 1줄, 모든 값 (대화 전문, 턴별 판단, 평가 원본, 분석, 이상 표시)
    sessions.csv    ← 실습 1회 = 1행 요약 (엑셀)
    turns.csv       ← 턴 1개 = 1행 (감정 변화, 판단 값, 종료 규칙 결과)
    meta.json       ← 실행 설정 (모델, 지시문 버전, 시나리오 버전)
  all_sessions.csv  ← 실행할 때마다 계속 쌓이는 누적 파일
  all_turns.csv
```

`simulations/` 는 `.gitignore` 에 들어 있어 저장소에 올라가지 않습니다.

## 리포트 보는 법

1. **시나리오 × 케이스 표**: 칸 색이 빨강이면 기대 결과 실패 또는 오류, 노랑이면 주의 표시. 칸을 누르면 그 대화로 이동.
2. **자동으로 찾은 이상 (코드별)**: 같은 코드가 여러 시나리오에 반복되면 시나리오 문제가 아니라 **지시문·종료 규칙 쪽** 문제일 가능성이 큽니다.
3. **기대 결과 실패**: 케이스마다 "서비스 규칙상 이렇게 돼야 한다"는 기대가 있고, 실제가 다르면 여기 모입니다.
4. **실습별 상세**: 턴마다 수강생 말 · 고객 말(응답 시간, 마무리 지시가 붙었는지) · 감정 변화(원값 포함) · 판단 AI 값(해결/고객 종료/상담원 인사/이관 수락 + 근거 한 줄) · 종료 규칙 결과 · 이상 표시.

이상 코드 뜻은 `checks.ts` 의 `CODE_INFO`, 케이스별 기대 결과는 `cases.ts` 에 있습니다.
